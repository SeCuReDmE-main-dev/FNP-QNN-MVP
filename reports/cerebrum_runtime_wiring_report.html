Cerebrum Runtime Wiring Report

Date: 2026-06-11

Objective

Wire the simulator to a real Cerebrum-shaped runtime contract without importing the legacy Cerebrum runtime directly. The simulator now accepts interval memories, builds deterministic crossmodal pairs, converts those pairs into the existing feature bundle, and sends the result through the QNN nucleus or torch fallback.

What Changed

  • Added core/cerebrum_runtime_bridge.py with CerebrumMemoryEvent, CrossModalPair, CerebrumRuntimeState, and CerebrumRuntimeBridge.
  • Updated core/cerebrum_adapter.py so flat observations and interval-shaped records both work.
  • Added core/life_science_port.py as a dormant, opt-in FFED/LVFM StateField-shaped observation port.
  • Added runtime API endpoints for status, ingest, pairs, and run.
  • Added command-handler support for cerebrum-runtime-* commands.
  • Added examples/cerebrum_runtime_demo.py.
  • Added runtime bridge and API tests.

Current Runtime Contract

Inputs can use memories, events, observations, grouped modality collections, or an optional statefield payload.

Each runtime event includes modality, starting time, ending time, duration, value, source, label, payload reference, and provenance. Each crossmodal pair includes timestamp1, timestamp2, direction, source modality, target modality, and overlap score.

Design Decisions

  • The old Cerebrum code is not imported into FastAPI.
  • The bridge implements the portable crossmodal interval-overlap contract.
  • The simulator remains runnable without Qiskit through the torch surrogate path.
  • FFED-RNASeq remains outside the simulator runtime and can later connect through the dormant StateField-shaped port.
  • Public wording stays research-oriented and makes no clinical claim.
